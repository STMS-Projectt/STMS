# المرحلة السادسة — دورة العطاء في Chrome

البيئة: Chrome Headless عبر DevTools، Kestrel على localhost، Identity بحسابات اصطناعية مستقلة وكلمات مرور فعلية، وقاعدة SQL Server LocalDB عشوائية. لم تُحقن هوية في مسار المتصفح ولم تُفرض حالات العمل عبر SQL. بعض الحسابات مجهزة مسبقًا بصف Passkey اصطناعي لتجاوز شاشة الإعداد عند اختبار كلمة المرور؛ اختبار Passkey المنفصل سجل واستخدم مصدق Chrome الافتراضي فعليًا. لم تُمس قاعدة المشروع.

| الاختبار | الخطوات والأدوار | حالة التحقق |
|---|---|---|
| A الترسية | القسم: مسودة، بندان وإرسال. المسؤول: قبول وإنشاء عطاء، معيار 100% وثلاث دعوات ونشر بعطاء مفتوح. ثلاثة موردين: قبول وتسعير ورفع وإرسال. المسؤول: إغلاق ومطابقة وتكليف. المقيمون الأربعة: درجات وتسليم. المدير: إعداد التقرير، ثم اعتماد المسؤول وموافقة المدير المستقلة. أربعة أعضاء يصوتون تباعًا، ثم فحص نتيجة العروض الثلاثة. | PASS لمسار الترسية مع الفتح الفوري. شرط تجربة Published بموعد مستقبلي في Chrome لم يُنفذ؛ لا يُعد تغطية كاملة لكل متطلبات A. |
| B الجولات | عرضان في الجولة الأولى؛ إعادة الفتح مرتين من الواجهة، وإعادة دعوة من لم يرسل عرضًا. إغلاق الثالثة والمطابقة ثم التكليف. | PASS لعرضين وعرض واحد؛ بقي العطاء Closed عند صفر. رفضت المحاولات المباشرة فتح جولة رابعة في الحالات الثلاث، وأكدت SQL وجود ثلاث جولات فقط. |
| C الإلغاء | بناء عطاء مستقل وإكمال التقييم والاعتماد؛ عضو لجنة يرفض بسبب؛ عضو آخر لا يجد إجراء التصويت؛ المدير يحيل إلى المسؤول؛ المسؤول ينشئ مسودة بديلة للطلب نفسه. | PASS. |

التشغيل النهائي: 39 اختبارًا آليًا ناجحًا، منها مشغّل واحد نفّذ 18 حالة Chrome ناجحة (13 سابقة و5 جديدة). في الترسية تؤكد SQL أربعة تسليمات، أربعة أصوات، عرضًا فائزًا وعرضين غير فائزين وثلاثة إشعارات. وفي B بقي العرضان من الجولة الأولى مع خمس محاولات دعوة. وفي C بقي العطاء الملغى والتقييمات والتصويت، والمسودة الجديدة للطلب نفسه بلا عروض منقولة. تحقق Chrome كذلك من منع مورد ثان من الوصول لعرض المورد الفائز ومستنده. لم يُنفذ منع التعديل بين قسمين، اختبار مقيم غير مكلّف، أو اختبار POST لتصويت حساب غير مخول عبر متصفح في هذا التشغيل؛ لا تعوض عنها اختبارات HTTP الأقدم.

إعادة التشغيل: اضبط `STMS_PHASE2_TEST_SQL` على مثيل اختبار، و`STMS_BROWSER_EXE` على Chrome ثم شغّل `dotnet test SourcingTenderSystem/SourcingTenderSystem.slnx -c Release`. مصادر خطوات الاختبار: `phase6-lifecycle.mjs`، `phase4-browser.mjs`، `BrowserReleaseTests.cs`.
