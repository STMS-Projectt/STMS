# المرحلة الرابعة — نتائج الاختبار

البيئة: Chrome Headless عبر DevTools Protocol، Kestrel على localhost، قاعدة LocalDB باسم عشوائي STMS_Phase4، وحسابات Identity اصطناعية مع جلسات حقيقية. اختبارات HTTP السابقة تستخدم هوية اختبار في مساراتها ولا تُحسب ضمن حالات Chrome. شُغّل خط الأساس: 38 PASS. التشغيل النهائي: 39 اختبارًا آليًا ناجحًا منها مشغّل واحد ينفذ 13 حالة Chrome، وجميعها PASS. لم يسجل Chrome استثناءات JavaScript غير معالجة. انظر [نتائج Chrome المسجلة](phase4-browser-evidence/results.json) للحالة والسبب الفعليين.

## نطاق دورة العطاء

- A: خطوات القسم إلى Under Review منفذة في Chrome. اختبارات المرحلة الثالثة أعادت إثبات التقييم والتصويت والترسية والإشعارات على HTTP وSQL. التسلسل الكامل من الطلب إلى الترسية في Chrome: **NOT EXECUTED**.
- B: جولات وإعادة فتح وقيد عدم التكرار وحفظ السجل مختبرة على HTTP وSQL ضمن المرحلة الثانية. التغطية الكاملة للجولات والحالات الحدية في Chrome: **NOT EXECUTED**.
- C: الإلغاء، إحالة المدير، وإعادة الطرح مع حفظ التاريخ مثبتة على HTTP وSQL. تسلسل Chrome الكامل: **NOT EXECUTED**.
- ترقية DB: إنشاء فارغ وتشغيل جميع الترحيلات، وترقية مخططات سابقة ببيانات اصطناعية؛ لا نسخة من بيانات المشروع الفعلية في هذا الاختبار. لم تُعدّل أي قاعدة غير قواعد الاختبار.
- عزل الموردين والمقيمين عبر كل معرّف، انتهاء الجلسة، التحقق من محتوى PDF وQR والتوقيع والتصدير وOllama: **NOT EXECUTED** في Chrome. FaceLab الحقيقي **BLOCKED** دون مفاتيح مجانية وبيئة كاميرا اختبار. WCAG وعتاد Passkey فعلي والميكروفون الحقيقي: **NOT EXECUTED**.

## إعادة التشغيل

عبر PowerShell، اضبط `STMS_PHASE2_TEST_SQL` على مثيل LocalDB تجريبي و`STMS_BROWSER_EXE` إلى Chrome أو Edge. من جذر المشروع شغّل `dotnet test SourcingTenderSystem/SourcingTenderSystem.slnx -c Release`. يتطلب Node.js 22+، ولا يعتمد على Playwright أو خدمة مدفوعة. ينشئ الاختبار قاعدة عشوائية ويحذفها بعد التشغيل. يعرض ملف نتائج المتصفح الحالات واستثناءات JavaScript غير المعالجة.

لاستكمال التحقق يدويًا: على نسخة SQL معزولة أنشئ حسابات منفصلة للموردين الأربعة وأعضاء اللجنتين. نفّذ طلبًا ببندين، ثم ثلاث دعوات وعروض كاملة، وأغلق العطاء، وسجّل التقييمات الأربعة ثم الاعتماد والتصويت. أعد السيناريو بعرضين وبعرض واحد عبر ثلاث جولات، وجرّب الرفض وإعادة الطرح. بعد كل خطوة قارن الحالة والصفوف والأصوات والإشعارات بدليل الشاشة. كرر الوصول المباشر من حساب مختلف واختبر النوافذ بلوحة المفاتيح مع شبكة بطيئة.
