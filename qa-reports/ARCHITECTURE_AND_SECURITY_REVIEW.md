# مراجعة الهندسة والأمن

ASP.NET Core MVC على .NET 10، EF Core/SQL Server، Identity/Passkeys، Razor وBootstrap وJavaScript. Controllers لتمرير عمليات العمل، Services للتوقيت والتحليل والتواصل وPDF والتخزين. قواعد الحالة نصية وموزعة بين Actions وViews وServices، مما أدى إلى اختلاف معايير تفسير الحالة. لا توجد مجموعة اختبارات ضمن الحل الذي فُحص. اجعل قواعد الانتقال والتفويض في خدمات نطاق قابلة للاختبار.

| الطبقة/الكيانات | الدليل والنتيجة |
|---|---|
| Identity / EmployeeProfile / SupplierProfile / Department | ملفات تعريف مربوطة بالمستخدم؛ صلاحيات إدارة منفصلة بالأدوار؛ تضارب الأدوار وسياسة تعطيل المستخدم تحتاج اختبار حالات. كلمات المرور عبر Identity، CSRF عالمي Program.cs:31 وثبت لمسار واحد. |
| Requisitions / Items / Tenders | FK وقيود حذف؛ Items تابعة للطلب؛ Tenders علاقة 1:N في ApplicationDbContext وAllowTenderHistory؛ سلامة index في قاعدة المشروع القائمة لم تُفحص. |
| Invitations / TenderSuppliers | Invitations تؤدي دور الربط ولا يوجد كيان TenderSuppliers مستقل؛ تاريخ كل جولة غير ممثل؛ Edit يسمح بإعادة ربط سجل B07. |
| Bids / BidItems / BidDocuments | فحص مسبق للعرض ومجموع الأسعار؛ لا قيد فريد فعال للعرض حسب المورد في النموذج؛ لا rowversion؛ B05/B17. ملفات عروض تحت App_Data ويُستخدم GetFileName. |
| Criteria / TechnicalEvaluation / FinancialEvaluation | FK وRestrict/ Cascade حسب ApplicationDbContext:155–193؛ لا سجل تسليم مستقل؛ ما يلزم uniqueness مركب للمقيّم/المعيار/العرض واختبار معاملات التزامن. |
| Reports / Approvals / CommitteeMembers | تقرير 1:1 للعطاء؛ موافقات مرتبطة بالتقرير والمقيّم؛ الحسم والإشعارات ضمن Serializable؛ لا يوجد قيد مركب صريح يمنع تكرار العضوية أو التصويت عند كل مسارات الإدخال. |
| Clarifications / Notifications / AuditLogs | FK للأطراف والمعاملات؛ البحث في المحادثات بالمشارك؛ تقييد الرد بالمرحلة؛ لا قيد قاعدة يلزم اختيار طرف واحد لكل جهة أو مرجع معاملة واحد؛ التدقيق غير شامل لكل انتقال. |
| الأداء | Compliance.Pending يستعلم عن الأعداد لكل عطاء مغلق؛ Notifications وClarifications تُحمّل القائمة دون صفحات؛ header يستعلم عن ملف المستخدم والعداد؛ لا قياس حمل منفذ. |
| الترحيلات | SQL bootstrap نجح في قاعدة اختبار؛ وجود ترحيلات يدوية وترحيل مولّد وتصحيح passkeys يستدعي مقارنة نموذج/SQL وترقية قاعدة قديمة؛ dotnet-ef غائب. |

أولوية الأمن: B01/B02/B03. التحقق بالكاميرا JPEG بلا liveness؛ لا تجرّبه بحساب حقيقي. تخزين صور في Git منفصل عن منع الوصول عبر middleware (B12). روابط QR لا تحمل سرّاً؛ الحماية من مسار العرض نفسه. HSTS في الإنتاج وHTTPS/Identity وحماية POST موجودة؛ لم تُقَس سياسة CSP/headers عبر proxy. المخرجات Razor تهرّب النص في المسارات التي فُحصت؛ workspace يعيد تشغيل سكربتات صفحات نفس الأصل وواجهة AI تُدرج HTML، فلا تعامل بيانات مزود خارجية كنص موثوق قبل التأكد من escaping. استعلامات EF parameterized عادة؛ SQL الترحيل ليس مدخل مستخدم. أي حكم أوسع حول XSS/SQL injection يحتاج اختبارات مستقلة.

الملفات: فحص توقيع PDF وحجم الملف لا يعادل فحص المحتوى والبرمجيات الضارة. تحقق من الملفات التالفة والمشفّرة وحدود تكلفة المعاينة وPDF signing؛ لا تُرسل أصل غير موسوم إذا فشل التحويل. فصل إعدادات المفاتيح، سجلات تدقيق أمنية بلا بيانات اعتماد، وإدارة إصدارات/احتفاظ للتقارير. تضارب الحفظ بين قاعدة البيانات والملفات يحتاج اختبارات فشل وتنظيف آمن.

Ollama: الخدمة تحضّر حقائق وتتحقق من بنية مخرجات النموذج؛ عنوان المضيف قابل للتوجيه ومهلته قابلة للضبط؛ لا تظهر عملية ترسية آلية تابعة للنموذج. تحقق من النموذج، مهلة الخدمة، سرية البيانات، ومدخلات قد تؤثر على التعليمات؛ B15. لم يُدعَ أي مزود خارجي خلال التدقيق.
